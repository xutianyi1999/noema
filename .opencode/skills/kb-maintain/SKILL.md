# Noema 内容库维护

当前目录是内容库根目录。维护任务的用户消息会给出唯一工作区 `staging/<job_id>`；只在这个工作区内读取和修改。库根保存正式内容，不能直接修改。

先阅读任务工作区内的 `purpose.md` 和 `schema.md`。

- 将发生变更或被删除的文本资料与受影响的 `wiki/` 节点重新对齐。
- 清理失效的来源引用和关系，但保留其他资料共同贡献的共享节点。
- 检查重复概念、相互冲突的声明、孤立节点和过期的生成产物。
- 保持原始资料不可变。使用上游 graphify Skill/CLI，并以 `staging/<job_id>` 为目标；不要创造内部知识库 MCP 工具。
- 将有歧义的修复放到 `reviews/`，并保留证据路径。
- 不要修改工作区中的 `.opencode/`、`library.sqlite`、`raw/`，也不要修改内容库根目录或项目外路径。
